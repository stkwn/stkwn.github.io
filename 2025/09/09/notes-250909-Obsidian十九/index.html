Obsidian完全入门之十九：Obsidian与编程IDE的美丽邂逅

发表于2025-09-09|更新于2025-09-09|notes
|浏览量:

1 前情回顾

之前我写过一篇把obsidian文章发布到博客的文章，我的数字花园也上线了。有些朋友还挺感兴趣的。

狄更斯说过一句话：这是最好的时代，也是最坏的时代。 没想到多年之后也依然适用。AI的出现改变了太多的事情。例如，10年前如果你问我非科班出身能转行做程序员？我可能会说很难。

但是，现在只要有一个好的想法，AI就能帮助你把想法变成现实。 我不是说它能一步到位，但做个MVP，确实没有那么难了。

你所需要做的，往往只是带着一点好奇、带着一点勇气，迈出第一步。

也许你会想：这些我有什么关系？IDE 不就是程序员才会用的工具吗？

其实并不是。IDE 跟我们每天用的笔记软件、知识库管理工具，有着很多相似之处。甚至，当你把两者结合起来，说不定会大吃一惊，原来Obsidian和编程IDE的碰撞，可以产生那么美妙的火花。

我今天想和大家分享的，其实就是这第一步。

而当你踏出这一步的时候，一定可以遇见更美丽的风景。

2 编程IDE到底是什么

2.1 什么是IDE

IDE，中文叫做集成开发环境，它是程序员用来编写、调试和运行代码的工具集合。我们现在最常用的IDE之一就是微软的Visual Studio Code，简称VS Code。

VS Code是一个轻量级但功能强大的代码编辑器，支持多种扩展插件。

其实，Obsidian和VS Code有很多相似之处。所以我说，如果你已经熟悉了Obsidian，那么你会发现，学习VS Code并不难。

2.2 Obsidian与VS Code的相似之处

  1. 界面布局：Obsidian和VS Code都采用了侧边栏和主编辑区的布局，方便用户同时查看多个文件和工具。

    例如，vscode也一样分侧边任务栏、文件浏览区、编辑区，与Obsidian非常相似。

  2. 文件管理：两者都支持文件夹和文件的层级结构，方便用户组织和管理大量的文件。你既可以通过上方的按钮创建新文件和文件夹，也可以点击文件夹右键创建。

  3. 命令面板：Obsidian的命令面板和VS Code的命令面板类似，可以通过快捷键快速访问各种功能和插件。

  4. 插件系统：两者都有丰富的插件生态系统，用户可以根据需要安装各种插件来扩展功能。

我这里就不一一列举了，总而言之，熟悉了Obsidian的用户，学习VS Code会非常快。

2.3 VS Code的本质

VS Code的是一个代码编辑器，但它的本质是一个高级文本编辑器，它可以用来编辑和管理各种类型的文本文件，包括Markdown文件。

而Obsidian说白了，也是一个Markdown编辑器。于是，Obsidian的仓库，可以直接用VS Code打开。

而Vscode的强大功能，更是可以帮助我们更高效地管理和编辑Obsidian的笔记。

所以，你完全可以把 Obsidian 当做“日常的笔记本”，把 VS Code 当成“笔记的加工厂”。前者负责记录灵感和输出，后者负责整理与打磨。

3 安装VS Code 和 插件

3.1 安装VS Code

VS Code的安装非常简单，直接去官网（https://code.visualstudio.com/Download），下载对应操作系统的版本，进行安装即可。

安装完毕，你就可以在桌面上找到VS Code的图标，运行VS Code。这跟你运行Word没有什么两样的。选择文件里的“打开文件夹”，再选择你的Obsidian笔记目录，就可以看到你的所有笔记了。

3.2 安装插件

Obsidian的强大之处在于它丰富的插件系统，而VS Code也是如此。我们可以通过安装各种插件来扩展它的功能。

对于我们使用Obsidian的用户来说，以下几个插件是非常有用的：

  1. Markdown Preview Enhanced：这个插件可以增强Markdown的预览功能，支持更多的Markdown语法和功能。下图中右侧就是这个插件的预览效果。

  2. Github Copilot“：这是一个AI助手，可以帮助我们通过AI来处理笔记。它可以根据我们的指令，生成相应的内容，甚至可以帮我们执行很多操作。
    但是，这个插件是收费的。个人用户每月10美元，可以免费适用30天。
    类似的AI插件，例如Cline，Claude Code，还有Qwen等，估计都是大同小异，大家可以自行选择。

  3. Cline：它也是一个开源的 VSCode 插件，它可以直接在VS Code中调用AI模型，例如ChatGPT、Deepseek等。它的作用跟Github Copilot类似，但是它是免费的。只不过API大部分是要钱的。如果你没有开通Github Copilot或者Claude Code等，你也可以用这个插件。

AI的工具其实有很多，大家可以自行选择。而本文则主要用Github Copilot来演示。

4 Obsidian笔记与VS Code的邂逅火花

当我们在VS Code中打开Obsidian的笔记目录后，我们就可以看到所有的Markdown文件了。利用Github Copilot插件，我们可以直接对这些Markdown文件进行AI辅助编辑。

4.1 批量修改笔记的元属性

我们可以利用AI来批量修改笔记的元属性。例如，我发现之前的一些公众号文章，当时写的时候，是没有元属性的。他们就是一篇普通的笔记。后来，我创建了公众号文章模板，我希望对这些笔记，添加上同样的元属性。

我只需要在github copilot的对话框中，输入相应的指令，AI就会帮我生成相应的元属性内容。

处理完了，这下面的几篇笔记，就都添加了相应的元属性。 哪怕你有更多的文件，AI也能生成统一格式的元属性，而且速度真的很快。

4.2 批量生成笔记的摘要

后来，我又发现，虽然笔记的元属性都添加了，但是它没有摘要，于是我让AI帮我根据笔记内容，生成相应的摘要。很快的AI又完成了我的任务。

这是一篇”关于AI编程工具是否提效”的文章，AI帮我生成了摘要如下：

本文深入探讨了斯坦福大学一项针对十万名程序员的研究，揭示了AI对开发效率的复杂影响。研究发现，虽然AI在简单、全新的“绿地”项目中提效显著，但在复杂、庞大的“棕地”项目中优势大减，甚至因引入返工而降低净效率。AI的效能还受代码库规模和上下文长度的限制。文章总结，未来开发者的核心价值将从基础编码转向更高阶的架构设计、问题分解和精准引导AI的能力，成为AI的“指挥家”。

又例如这一篇，记录的是一次用AI编程的过程， AI总结如下：

大家觉得这效果是不是挺好的？

4.3 批量生成笔记的标签

标签对笔记管理很重要，但它也一直是我的痛点。

刚开始写 Obsidian 的时候，我并没有养成给笔记打标签的习惯。等到笔记越积越多，一篇篇看和补，发现几乎是不可能的任务。更糟糕的是，我的标签没有统一规范：有时写 AI，有时写人工智能，特有些标签下面还有子类，自己写了啥都忘了。

作为一名程序媛，我的 Vault 里什么都有：

  • 技术类的学习笔记
  • 产品相关的工作笔记
  • 各种tickets的记录

本来都应该有清晰的标签体系，可现实中却乱成一团。直到有一天，我把整个 Vault 用 VSCode 打开，抱着试试看的心态，让AI帮我统一规范标签。

AI不仅能识别每篇文章的主题，统一标签风格。根据内容，还能帮我生成新的标签。

最重要的是，这些修改都是批量完成的，几分钟就帮我解决了过去几个月都不想碰的“整理大工程”。由于这部分的内容涉及公司隐私，我就不展示了。

4.3 多语言支持

最后，我想讲的是，我还可以让AI帮我翻译。比如我这篇Obsidian_从卡片盒到数字花园的实践，我让AI帮我翻译成英文。整个过程处理速度20秒。

先不说翻译质量如何，至少速度比我快，表达比我好。我可没办法再怎么挑刺了。 ## 3 结语

通过这次的尝试，我发现，Obsidian和编程IDE的结合，可以极大地提升我们的笔记管理效率。尤其是当我们面对大量的笔记时，AI的辅助显得尤为重要。

今天的文章我也只是展示了一些简单的用法，抛砖引玉。其实Obsidian的插件里，也有不少跟AI有关的插件。为什么我还要费这心思呢？

原因很简单：VS Code 能直接从“底层”处理文件，不受插件限制，而且只用一个工具就能搞定更多事情。 这意味着我们不必在不同插件之间来回切换，也不用担心功能碎片化。

你的笔记就像一座数字花园，Obsidian 是种子和土壤，而 VS Code 就是那个耐心而高效的园丁。两者结合，能让花园里的每一片叶子都更快地舒展开来。

而且，作为数字花园落地的一部分，这一篇笔记也是一篇先导文，毕竟没有编程IDE，也不太可能把数字花园搭建起来。
