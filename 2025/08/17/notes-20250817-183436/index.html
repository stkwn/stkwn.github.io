Obsidian完全入门之十一：用Obisidian搭建个人知识管理工作流

发表于2025-08-17|更新于2025-08-17|notes
|浏览量:

1 前情回顾

在上一节，我们介绍了卡片盒的故事。Luhmann通过卡片盒笔记法，创造了一个独特的知识管理系统，使他能够跨学科地连接相关概念，最终创作出超过70本书籍和400篇论文。你是不是也有点跃跃欲试，毕竟，Obsidian的设计理念就是为了让我们能够轻松地实现这种知识管理。

卡片盒笔记法提及了几种笔记类型，包括了闪念笔记、文献笔记、原子笔记、永久笔记等。今天，我们将探讨如何在 Obsidian 中搭建这样的个人知识管理工作流。

2 主要内容区域

2.1 工作流概述

如果你仔细观察，你会发现卡片盒笔记法的工作流可以分为几个主要步骤。知识管理和卡片盒笔记法等领域的实践者们在长期经验中总结出的一个简明的流程——CODE，目前已成为数字笔记和信息处理的主流流程之一。

CODE 在这里可不是代码的意思，它是四个英文单词的首字母缩写，分别代表：

  • Capture（捕捉）
  • Organize（整理）
  • Distill（提炼）
  • Express（表达）

例如，Luhmann每天都会捕捉新的想法，整理到卡片盒里，通过编号和链接不断扩展自己的知识网络，最后发表成文章或者书籍。CODE的核心也是如此，从捕获到表达，让笔记从一个状态转变为另一个状态，最终形成一个连接的知识体系。

那么，在Obsidian中，我们如何实现这个流程呢？不同的人会有不同的方法，本质上是因为，每个人的侧重点是不同的。

比如，作家可能更关注于如何将笔记转化为文章，而研究者可能更注重文献的整理和引用。而对我这种普通用户而言，可能更多的只是关注如何将捕捉到的内容进行整理，把它们变成有用的知识，并且在需要的时候能够快速找到。

今天，我就先分享一下我的工作流。

2.1.1 CODE 的第一步：C——Capture（捕捉内容）

2.1.1.1 闪念内容

我们的日常生活和工作中，灵感、疑问、见解、引用、观点随时可能出现。如果不及时记录，这些内容很容易被遗忘。捕捉的过程，就是把这些“闪光点”变成可以管理和复用的卡片，为后续的整理和扩展打下基础。

对于我而言，我常常捕获的内容包括：

  • 突然冒出来的新想法
  • 读书、视频、博客的重点摘录
  • 工作中的问题和解决方案

对于这些闪念笔记，我总是会用创建时间戳笔记的方式，快速记录下来。 它是Obsidian的核心插件，你可以通过设置按钮，进行设置。

比如在这里，我们可以设置：

  • 笔记的标题格式： YYMMDD-HHMM意味着标题会自动生成类似240722-2230的格式。
  • 闪念笔记的模板： 可以预先设定一个简单的模板，这个模板我只包含了创建时间，标签和到上级的链接。下方添加一个相关链接。正文就是填写闪念内容，而链接则是记录促发这个闪念的来源。
  • 笔记的存储位置：我将它们存储在一个统一目录下。

接着，每次像创建笔记的时候，就可以点击侧边栏的创建时间戳笔记按钮，快速创建一个新的笔记。

2.1.1.2 剪藏内容

对于网络上的内容，我则会使用Web Clipper插件，直接将网页内容保存为Obsidian笔记。这样可以保留原始链接和格式，方便后续整理和引用。它们会直接放置在Clippings的目录中。

在该目录下，我又设置了公众号、掘金、youtube、得到等子目录，方便我进行分类。由于剪藏工具也允许我设置模板，设置存放目录，所以这一个过程确实是挺高效的。

比如，最近Get笔记遭遇腾讯的举报，我觉得这还真是大事件，于是就使用了Web Clipper插件，将相关的报道和评论剪藏下来。

2.1.1.3 读书笔记

对于读书笔记，我喜欢边读边记录，因此，我也创建了一个专门的模板，方便我快速记录书籍的要点、笔记和摘抄等内容。

这里的预设工作主要包括：

  • 读书笔记的模板
  • 创建某本书的读书笔记
  • 链接MOCs（Map of Content）笔记

我的读书笔记模板相对简单。就拿我最近读的《原子习惯》来说，这里有张笔记

这个笔记，套用的是我预设的读书笔记模板。它包含了元属性和正文两部分。元属性是允许我用dataview获取信息的部分，设置了书名、作者、标签等信息。你可以注意到这里有个up，其实到上级Mocs的链接，这样我就可以快速回到MOCs笔记中。

正文部分则是我对书籍内容的要点、笔记和摘抄等内容的记录。我基本上会在阅读过程中，边读边记录，把我觉得有意思的内容写在4 摘抄部分。书中提及的其他参考资料放在6 链接里，书中出现的其他引用放在3 引用部分。 而我自己的总结则会放在2 笔记部分。
如果书里某一个地方触动了我，我会在5 想法部分添加自己的想法。

#### 2.1.2 CODE 的第二步：**O——Organize（整理内容）**

捕捉到的内容只是知识的起点，真正让这些信息变得有价值，还需要经过“整理”这一步。对我来说，整理是一个主动回顾和筛选的过程。

每天的日记（Daily Notes）模板中，我都会用dataview自动更新当天查看和创建的笔记链接。这些链接就像是一天中知识流动的“足迹”，方便我在回顾时快速定位当天捕捉到的灵感和信息。

在整理阶段，我会对闪念笔记扫除活动：
- 这条想法是否值得保留？如果没有用，就果断地删除掉。
- 这条想法是否需要进一步扩展？如果是，就将其转化为永久笔记或原子笔记。
- 如果这是一个重要的引用或观点，我会将其链接到相关的文献笔记中去。

而对于剪藏文章和读书笔记，因为模板包含了正文内容或者摘抄，所以这个阶段，我主要就是来画重点了，进行高亮标记，或者进行简单的总结。

#### 2.1.3 的第三步：**D——Distill（提炼内容）**

提炼是将捕捉和整理的内容进一步精炼成有用的知识。这个过程我基本只用在记技术方面的知识上。作为程序媛，我经常需要记录一些技术细节、代码片段和解决方案。这部分的分享对大家意义可能就不是很大了。

2.1.4 的第四步：E——Express（表达内容）

表达是将知识转化为实际成果的过程。公众号就是我尝试表达的方式，我对Obsidian的使用和个人知识管理的经验进行重新整理成文，就当作是一种练习了。

3 结语

这就是我在Obsidian中搭建个人知识管理工作流的初步尝试。通过捕捉、整理、提炼和表达，把零散的知识和灵感变成更广阔的知识体系。

我其实和大家一样，也还是个新手呢，我也在不断探索和完善这个流程。每个人的工作流都是不一样的，所以每个人都值得好好思考自己的需求和习惯，进行调整和优化。

但是总体而言，我们可以总结出几个关键点：

  • 捕捉：随时记录灵感和信息，使用模板和工具提高效率。
  • 整理：主动回顾和筛选内容，建立链接和分类。
  • 提炼：将信息精炼成有用的知识，特别是技术细节。
  • 表达：通过写作、分享等方式，将知识转化为实际成果。

同时，设置必要的文件夹和模板，例如：

  • 灵感笔记的临时存储目录
  • 剪藏文章和读书笔记等文献笔记的存储目录
  • 原子笔记和永久笔记知识库的存储目录
  • 项目式输出和的存储目录
  • 还有各类笔记模板。

最好这些准备工作，相信你就能非常顺利的启航了。
